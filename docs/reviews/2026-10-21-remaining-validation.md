## 1. 真实 Claude 完成提醒

`ReleaseSmokeValidation.exe <目录> --claude-chain`：独立配置、一个自有离屏窗口绑定 1 号槽位，通过产品的 `scripts/Start-TrackedSession.ps1` 在最小化 conhost 中启动**交互式** Claude Code，提交一条不需工具的短提示。会话在回复后保持打开，与日常使用一致。

| 时间（启动后） | 观察 |
| --- | --- |
| 2.5 秒 | 槽位转为 Running，来源 Claude Code hooks |
| 6.5 秒 | 转为 Ready，未读；会话 ID 已绑定，集成在线 |
| 7.4 秒 | 托盘气泡发出，系统回调 `NIN_BALLOONSHOW` 确认已显示 |

之后按任务 ID 结束测试会话，确认无残留进程；事件文件均已确认并清除。声音提醒在快捷键暂停时按设计不播放（测试为避免抢占使用者键盘而暂停快捷键），所以**本项不覆盖完成音的实际输出**；完成音的播放条件已由状态测试覆盖。

另用 `claude -p` 加同一组 hooks 复测两次（文件重定向、管道读取各一次），均 5–6 秒内完成，事件为 SessionStart/Unknown → UserPromptSubmit/Running → Stop/Ready → SessionEnd/Unknown。上午那次在 UserPromptSubmit 之后、模型回复之前停住，Stop 未触发，说明卡在请求阶段而非 OmniVibe 的 hooks；本机 Claude 经本地代理访问，当时的原因已无法确认。

注意：`-p` 模式会在 Ready 后不到 1 秒发出 SessionEnd，使状态回到 Unknown，可能来不及合并出提醒。这只影响一次性脚本调用，不影响交互式使用；如需支持脚本场景，可另行讨论 SessionEnd 是否应保留上一轮的 Ready。

## 2. Claude Code 中用户消息显示为灰色色块（使用者反馈，已修复）

**原因：** 不是粘贴的问题，手动输入的消息也一样。Claude Code 默认深色主题给 transcript 里的用户消息加中性灰底（约 `#373737`）。Windows Terminal 对程序显式指定的单元格背景色一律不透明绘制，只有默认背景会透出插画。在 Terminal 中实测：中性灰、套装底色、调和色三行全部不透明，无 SGR 的行透明。因此 OmniVibe 无法让该底色透明，只能改它的颜色。

**修复：** Claude Code 2.1.118 起支持 `~/.claude/themes/*.json` 自定义主题，只覆盖指定颜色、其余沿用内置主题。设置中“保存并应用”主题时，若存在 Claude Code 配置目录，会同步写入 `themes/omnivibe.json`：

- `userMessageBackground` / `memoryBackgroundColor`：套装底色向强调色混合 12%（遗迹为 `#312E24`，原为中性灰）；
- `userMessageBackgroundHover`：18%；`!` 命令底色：向前景混合 10%；选区：套装选区色；
- 浅色套装（梦幻西游）以 `light` 为基础，其余以 `dark` 为基础。

只写这一个文件，不修改 Claude 的主题选择或其他设置。使用者在 Claude Code 中执行一次 `/theme` 选择 **OmniVibe**，以后切换套装会自动跟随（Claude 监视该目录并热重载）。首次创建 `themes` 目录时需重启 Claude Code 一次。

本机已按当前遗迹套装放置该文件；Claude Code 设置未改动。

## 3. 整日运行与休眠唤醒

已在后台启动 `Watch-DayRun.ps1`（PID 51564，12:34 开始，26 小时，每 5 分钟一次）。它只读采样正在运行的 OmniVibe：私有内存、工作集、句柄、线程、GDI/USER 对象、CPU 时间、是否响应，并记录 DLL 哈希；两次采样的实际间隔远大于 5 分钟时标记为疑似睡眠，结束时汇总系统电源事件（Kernel-Power 42/107 等）。不操作窗口、配置或任务。

边界：被观察的是使用者当前运行的 Debug 构建（`src/CodeManager/bin/Debug`，DLL 哈希记录在样本中），不是本轮 Release 构建；实际使用强度取决于当天操作。结果将在采样结束后另行汇总，**目前不能写成已通过**。若中途关闭或重启 OmniVibe，样本会记录新的 PID。停止观察：`Stop-Process -Id 51564`。

本机电源能力：仅 S3 睡眠；休眠、混合睡眠和快速启动均不可用。因此“休眠唤醒”在本机实际只能测睡眠唤醒。
