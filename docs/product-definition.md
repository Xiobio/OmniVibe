# OmniVibe 产品定义

> 本文定义产品方向和目标行为，并区分当前实现与待建设能力。当前源码、可执行文件和数据目录仍使用 CodeManager 名称；具体操作以[使用与开发指南](usage.md)为准。

## 产品定位

**OmniVibe — The Open-Source Task Inventory for Vibe Coding**

**让并行开发，像切换装备一样直觉。**

OmniVibe 是一款面向多 AI Agent 并行开发的 Windows 桌面任务装备栏，以完全开源、可切换皮肤和社区自定义皮肤为产品方向。

它运行在现有桌面和终端之上，通过窗口管理能力，将散落的独立 CMD、PowerShell、Windows Terminal 或 AI Agent 终端窗口绑定到固定槽位。用户通过快捷键和鼠标手势快速切换，通过任务总览查看工作现场，通过状态提示发现需要处理的任务，并自由选择或制作界面皮肤。

核心价值：让用户随时知道任务在哪里、正在做什么，以及什么时候需要自己。

## 目标用户与问题

面向同时管理多个项目、多个终端和多个 AI Agent 的开发者，尤其是经常在等待授权、查看输出和切换任务之间往返的用户。

需要解决的主要问题：

- 多个外观相似的终端难以辨认，切换时反复寻找目标。
- 最近使用顺序不断变化，难以形成稳定的位置记忆。
- 需要反复查看 Agent 是否仍在执行、是否等待输入、是否已回复或出错。
- 工作现场分散，重新进入项目时需要恢复任务与窗口关系。
- 工作台外观缺少选择，用户和社区难以独立定制。

## 设计原则

1. **位置稳定。** 任务拥有固定编号，不随使用频率、提醒或任务退出自动重排。
2. **直觉操作。** 收纳、切换、总览形成清晰一致的操作路径。
3. **即时响应。** 窗口操作立即执行，动效与音效随后反馈，不延迟切换。
4. **状态可信。** 有可靠事件才报告状态，无法判断时明确显示未知。
5. **提醒克制。** 状态变化不抢焦点、不改变槽位；装饰不遮挡任务信息。
6. **外观开放。** 窗口管理、任务状态与界面表现分离，允许社区独立制作皮肤。

## 核心交互

### 固定槽位：The Hotbar

- 提供 1–9 号任务槽位，默认放在屏幕右侧。
- 支持拖动已有窗口标题栏到空槽，或通过窗口选择器绑定。
- 槽位展示编号、名称、项目、状态和窗口入口。
- 收纳可以最小化原窗口，后台任务继续执行。
- 已占用槽位不能被意外覆盖。
- 不按最近使用顺序或任务状态自动排序；删除任务后，其他任务保留编号。
- 用户可以主动移动任务或交换槽位，编号变化应明确可见。
- 移出任务解除管理并恢复窗口，不结束终端或 CLI。

首版管理单位为独立窗口。Windows Terminal 内部标签页和分屏不作为独立绑定对象。

### 快速切换：Weapon Switch

- `Alt + 1–9` 直达对应任务。
- `Alt + 滚轮` 连续切换，每一格滚动立即进入目标窗口。
- 窗口唤出先于视觉转场，音效和动画不阻塞输入。
- 快捷键和手势可配置，提供暂停和冲突提示。
- 音效和动画可分别关闭。

### 任务总览：Tactical Inventory

总览以卡片矩阵展示任务编号、名称、项目、窗口预览和状态。用户可浏览任务、进入目标窗口、收纳新窗口或重连已断开的任务。

- 打开总览不移动、排列或最小化已有任务窗口。
- 关闭总览回到之前的工作现场；进入任务时才唤出目标窗口。
- 支持键盘、鼠标和编号选择。
- 目标支持“按住查看、松开返回”与“按一下打开、再次关闭”两种模式。
- 总览按键可配置，默认方案应避免占用终端常用补全操作。
- 窗口预览尽量保持更新，最小化等系统限制下不承诺实时画面。

### 状态感知

通过 Agent hooks 或适配接口接收可靠事件，将任务状态转化为可快速辨认的视觉反馈。

| 状态 | 产品含义 | 表现方向 |
| --- | --- | --- |
| 运行中 | Agent 已报告正在执行 | 轻量流动或微光 |
| 等待处理 | 需要授权、回答或其他人工操作 | 明确文字、图标与呼吸提示 |
| 本轮已回复 | 当前一轮输出结束，可以查看结果 | 完成标记与未读提示 |
| 错误 | 收到明确失败事件 | 错误标记与短促视觉提醒 |
| 未知 | 尚未接入，或缺少可靠状态 | 中性样式和未知说明 |

窗口连接状态独立展示。窗口存在不代表 Agent 正在执行，窗口断开也不直接等同于任务报错。

未接入状态时不根据输出频率猜测任务是否完成。“本轮已回复”不代表整个开发任务已经完成。查看任务可以清除未读提示，但不擅自改变其执行状态。

提醒不抢焦点、不重排槽位；文字与图标共同表达含义，不能仅靠颜色区分。

### 工作现场恢复

保存任务名称、项目、槽位、窗口关联和恢复配置，支持重新连接已有窗口，或按明确配置打开终端与指定 AI 会话。

恢复不自动提交提示词，不以“最近一次会话”替代缺失的会话 ID。恢复终端不意味着恢复进程内存、未保存输入或任意后台命令。

## 开放皮肤系统：Omni 引擎

### 定义

用户可以切换完整视觉风格，社区创作者可以独立制作、分发和维护皮肤包。

皮肤覆盖材质、形状、字体、图标、装饰布局、动效和音效。水墨武侠、赛博 HUD、像素街机、极简毛玻璃等风格应能形成明显差异。

### 两级定制

| 层级 | 定制范围 | 面向用户 |
| --- | --- | --- |
| 主题配置 | 配色、字体、透明度、背景、动效强度、声音开关 | 希望快速调整外观的用户 |
| 完整皮肤包 | 侧栏与卡片外观、装饰布局、图标素材、状态表现、转场、音效 | 设计师与社区开发者 |

### 稳定契约

所有皮肤使用相同的任务数据、状态语义和操作接口。皮肤负责表现，核心负责窗口调度、输入、状态、持久化和恢复。

- 切换皮肤不重启终端、不中断 Agent、不丢失任务绑定。
- 皮肤不修改任务编号、状态、快捷键含义或窗口管理规则。
- 不同风格可以使用不同装饰名称，但保留可读的真实状态文字。
- 动画、声音和装饰效果可以关闭；重要信息在关闭特效后仍然可用。
- 布局变化不能破坏编号识别、操作入口和基础可读性。

### 皮肤包与使用流程

皮肤规范应覆盖标识、名称、版本、作者、兼容版本、许可证、预览图、主题配置和素材引用，并提供稳定的组件与状态表现接口。

用户流程：预览 → 导入本地皮肤包 → 切换使用 → 卸载或恢复默认。缺失素材和版本不兼容时提供明确提示，并支持回退到默认样式。

普通皮肤包采用声明式配置和素材文件。需要执行代码或调用系统能力的扩展另设插件机制。具体文件格式与渲染方案在实现阶段确定。

### 官方与社区皮肤

以当前“水墨机关术”为第一套官方皮肤，再提供一套极简或赛博风格，检验接口能否承载明显不同的视觉表达。

提供最小示例、素材规范和兼容性说明。作者无需修改核心源码即可制作和安装皮肤；用户可以从本地文件导入，后续再建设在线目录和社区分发能力。

## 开源方向

- 核心程序、官方皮肤和皮肤规范开放源码。
- 提供完整构建说明、贡献指南和皮肤制作示例。
- 社区作者可以独立发布皮肤，并声明各自的许可证信息。
- 核心功能可在本地使用，无需账号。
- 正式开源发布前，选定并添加许可证，明确官方美术、字体、音效和其他素材的授权范围。

“完全开源”是产品发布目标，不能仅以源码可见代替明确的开源授权。

## 技术方向与当前基础

当前项目采用 C# / WPF / Win32，已经具备窗口收纳、快捷切换、任务总览、状态接入和工作现场恢复等基础。

产品定义不绑定 Tauri、React、Tailwind 或特定 Web 组件格式。目标是在现有基础上分离窗口管理、任务状态与界面表现，再通过稳定的皮肤规范支持多种视觉风格。

### 当前实现与目标差异

| 项目 | 当前实现 | 产品目标 |
| --- | --- | --- |
| 槽位管理 | 1–9 编号；手动拖动任务可插入排序并重新编号 | 稳定位置，主动移动或交换，删除不触发其他编号变化 |
| 总览操作 | 按一下 Tab 打开或关闭，默认全局接管 | 提供两种触发模式，可配置且避免默认干扰补全 |
| 外观 | 水墨主题及墨玉、夜阑、朱砂内置配色 | 多种完整视觉风格，可独立制作和导入皮肤包 |
| 状态 | Claude Code / Codex hooks 和手动状态接口 | 维持可靠事件语义，逐步扩展适配能力 |
| 开源配套 | 本地开发源码，尚未添加许可证 | 明确许可证、贡献指南、皮肤规范及示例 |

此处描述的是实现基线和后续方向，不代表本次文档整理已改变程序行为。

## 首个正式版本范围

围绕“收纳任务 → 快速切换 → 查看状态 → 总览定位 → 切换皮肤”形成完整闭环。

交付要求：

- 独立窗口收纳、固定槽位、快速切换与解除绑定。
- 任务总览、窗口预览和明确的连接状态。
- 可靠的运行、等待、本轮已回复、错误和未知状态。
- 可配置快捷键、动画和声音，提醒不抢焦点。
- 任务配置保存及明确范围的工作现场恢复。
- 至少两套视觉差异明显的官方皮肤。
- 本地皮肤包预览、导入、切换、卸载与默认回退。
- 最小皮肤示例、制作文档、构建说明和明确的开源许可证。

在线皮肤商城、在线分发、复杂插件系统和更广泛的自动化能力放在后续阶段。

验收时，应能由社区作者参照示例、不修改核心代码，制作并导入一套新皮肤；切换后原有任务、状态、槽位和窗口操作继续正常使用。

## 对外介绍草案

> 以下文案用于对应能力和开源配套完成后的发布介绍。

OmniVibe 是一款完全开源的 Windows 桌面任务装备栏，为多 AI Agent 并行开发而设计。将散落的终端收进固定槽位，用快捷键直达任务，在总览中掌握工作现场，并及时发现需要处理的状态。通过可切换、可自定义的皮肤系统，你可以把自己的开发工作台塑造成赛博 HUD、武侠剑匣、像素装备栏，或任何属于你的风格。
