# macOS 原生开发预览

macOS 移植采用 SwiftUI / AppKit / Accessibility，沿用原版透明悬浮入口、九槽装备轮盘、主题图录与配装方式，直接使用仓库中的 13 套主题和 117 件器物素材。默认主题与 Windows 一致，为黑神话 / Relic。现有 Windows / WPF 工程继续独立构建；此阶段尚未把 Swift 与 C# 的实现合并为共享二进制核心。

## 构建与运行

需要 macOS 13 或以上及支持 Swift 5.9 或以上的 Xcode / Command Line Tools。无需额外下载第三方 Swift 包，在仓库根目录执行：

```sh
./scripts/macos/run.sh
```

本地应用生成在 `artifacts/macos/OmniVibe.app`。脚本使用本机架构，Apple Silicon 主机生成 arm64；Intel、Universal 包和不同系统版本尚需另行构建验证。`CONFIGURATION=release ./scripts/macos/build.sh` 可生成本机 Release 构建。

独立交付包位于 `artifacts/macos/delivery/OmniVibe.app`，最终验证日志为同目录的 `validation.log`。可通过 `OMNIVIBE_OUTPUT_DIR` 指定构建和验证报告的输出目录，例如：

```sh
OMNIVIBE_OUTPUT_DIR="$PWD/artifacts/macos/delivery" CONFIGURATION=release ./scripts/macos/validate.sh
```

打包优先使用本机已有的 Apple Development / Developer ID 证书，也可通过 `OMNIVIBE_SIGN_IDENTITY` 指定；没有证书时才使用临时签名。固定开发签名可让重编译保持同一签名身份；由旧临时签名切换后，仍可能需要重新授权辅助功能。当前 Mac 预览包使用 Apple Development 签名、尚未公证；正式公开分发仍需 Developer ID 签名、公证与独立系统验收。

重新构建后，请先正常退出已运行的 OmniVibe，再打开新应用；仅再次执行 `open` 会激活仍在运行的旧实例。

## 首次使用

1. 普通启动只显示桌面上的透明器物入口，核心点击区域固定为 54 pt。悬停只展开周围九槽装备，核心在展开 / 收起全程保持原屏幕锚点；面板尺寸立即调整，不以尺寸动画拖动核心。靠近屏幕边缘时，外围轮盘偏心移入可用区域，并以连接线指向原核心，槽位与移除按钮保持可见、可点击。按住左键拖动核心即可移动，右键打开管理菜单。原 13 套主题与 117 件器物均整图等比缩放，不裁切素材。
2. 右键 → 设置与辅助功能授权 → 通用，进入系统设置 → 隐私与安全性 → 辅助功能，为 **OmniVibe** 开启权限，再返回重新检查。未授权时可以浏览外观，窗口控制保持停用。
3. 点击轮盘空槽，选择一个真实窗口；同一终端的多个窗口可分别收纳。标题栏拖入通过窗口实际位置变化识别，不接管终端文本拖选。拖入完成后先将窗口恢复到拖动前的位置，再保存绑定；恢复失败则不建立绑定并显示原因。该路径仍需继续做不同终端的手工验证。
4. 默认 `Option + 1–9` 切换到具体任务。再次触发同槽时，只有目标窗口确实处于最前台才恢复原状态和先前焦点；若焦点已转到其他窗口，则重新进入该任务。切换前会收起管理界面，避免它遮挡目标。按住 `Option + Q` 呼出指向轮盘，松键进入；Esc 取消。设置 → 快捷键可立即切换为“Option + 空格打开总览后按数字”或保留原来的 Control + Option 组合；方案会保存。
5. 右键 → 打开主题图录，浏览九个固定槽位，支持方向键、数字与 Enter；Esc 返回。拖动卡片主预览区可插入排序；卡片右键可移到空槽、重命名、换配装、重新绑定或解除绑定。
6. 右键菜单或默认 `Option + 反引号` 排列 / 恢复窗口，即 Esc 下方的 `· / ～` 键，不需要 Shift；默认方案不再占用 Option + 0。当前均衡排列为两窗左右、三窗上二下一且底行铺满宽度，四窗起网格，末行按实际数量填满。按稳定物理屏幕标识分组，同屏使用一次可用区域快照，避免 Dock 动画改变边界时被分错组；排列时收起总览并置前目标窗口。全屏或不允许缩放的窗口会提前跳过并提示；应用拒绝目标尺寸时恢复整组原布局，无法恢复的快照仍保留。图录可选均衡平铺、分栏、分行和主窗居左。已连接表示能访问窗口，不保证该窗口能按要求排列；总览显示收纳 / 连接数量、本次排列摘要和持续保留的失败原因。主题与设置、右键主题菜单可切换 13 套外观；配装选择按任务和主题分别保存，自定义图片复制到受管目录。
7. 菜单栏仓鼠图标或默认 `Option + H` 找回 / 隐藏入口。此前的 Control + Option + Space 与系统输入源切换冲突，已替换。各快捷键独立注册，冲突只影响该键；设置的快捷键页显示实际注册结果与最近收到的明确快捷键。总览优先预设在未自定义时仅注册 Option + 空格，保留 Option 数字的字符输入。右键也可明确展开 / 收起装备轮盘。

应用退出时恢复本次仍由应用保存的布局；关闭主界面后可从菜单栏重新打开。退出恢复只覆盖仍在运行的窗口，不能恢复已关闭窗口或进程内部状态。

任务名称和绑定信息保存在 `~/Library/Application Support/OmniVibe/workspace.json`，不修改 Windows 的配置。默认允许重新连接仍在运行的原窗口：必须同时确认同一系统登录会话与本次系统启动、进程 ID 与启动时间、应用标识和 WindowServer 窗口编号，再唯一匹配当前辅助功能窗口。移动或改名不意味着新任务；身份缺失、匹配有歧义、目标应用已重启或旧配置缺少身份信息时保留断开状态，由用户重新绑定，不按标题猜测，也不启动应用。

冷重连使用稳定的 `kern.bootsessionuuid`、用户 UID 与登录 audit session 组合，成功后保留原任务 UUID 和窗口绑定。迁移旧 `kern.boottime` 记录时，仅在完整核对 PID、进程启动时间、应用标识和确切 CG 窗口后，兼容同一用户、audit session 与启动秒数下的微秒差异；不会放宽到不同进程、系统启动或登录会话。

损坏的工作区文件先按原字节备份，再允许保存新工作区。文件读取 / 写入失败会显示错误。

## 窗口偏好、滚轮与恢复

设置 → 通用 → **窗口与任务操作** 可即时保存唤醒方式（返回上次位置或铺满所在屏幕工作区）、收纳后最小化、窗口间距、排列时隐藏悬浮入口、总览大小与展开轮盘大小。展开轮盘继续使用原有 280–520 pt 大小设置，54 pt 核心不随之放大；已有大小偏好与入口锚点不迁移。排列方式也会保存。偏好校验或保存失败时保留原运行设置；损坏的偏好不会因打开设置而自动覆盖。

Lark 等应用在后台可能暂不提供辅助功能窗口。用户明确切换任务时，先验证原进程、启动时间、系统会话和确切 CG 窗口仍存在，再唤醒该应用并等待原窗口重新可访问；不会改绑到应用主窗口或启动替代进程。排列也先尝试唤醒所有尚未确认关闭、但暂不可访问的已绑定窗口，全部重新确认成功后才开始移动。任一唤醒失败或准备阶段被取消时不执行排列移动，并显示原因，避免三个已绑定窗口静默只排列两个；等待期间持续检查取消与原窗口身份。

默认按住 `Option` 纵向滚动可在已连接任务间循环切换，也可更换修饰键或关闭。启用前分别预检辅助功能和输入监控权限；缺少任一项时不安装滚轮监听，设置中显示原因，可打开权限页面后重新注册。预检不会代用户申请或授予权限。只匹配所选修饰键的纵向滚动才参与切换，触控板累计位移并限制连续切换，惯性不继续切换；暂停全部快捷键或录制组合时保留普通滚动。监听被系统停用会提示重新注册。

收纳最小化、任务唤醒与排列修改窗口前，将原位置、尺寸和最小化状态原子写入 `window-recovery.json`。未完成的恢复记录可跨 OmniVibe 重启保留；有待恢复记录时先恢复，或**保留备份并跳过**，再进行新的窗口变更。默认启动显示待恢复记录，自动恢复默认关闭，可在设置中明确开启。恢复仅操作能确认身份且仍存在的原窗口；权限不足、连接不明或恢复失败的记录保留供重试，不能恢复已关闭的进程、终端内容或 CLI 运行状态。损坏记录先备份，读取或备份失败时保留原文件并停止使用该记录。

任务窗口被确认关闭后自动进入 **最近关闭**，最多保留 30 条；临时失去权限、访问超时和手动移出管理不作为关闭归档。**恢复任务** 使用空槽重连原窗口，或打开具体窗口选择器；**启动／继续…** 则在用户确认配置后创建新的 Terminal 任务，可续接确切 CLI 会话。恢复会重置旧运行状态、未读和会话连接；重新启动迁移任务名称、启动配置和配装，成功后移出最近记录。手动移出管理会清理该任务的启动与会话关联元数据，保留原窗口。

任务完成提示音可单独关闭；系统任务通知默认关闭，只在明确开启时申请通知权限。通知只含任务标题和固定状态，点击按任务 UUID 查找当前任务，不按旧编号切换。系统接受通知请求不代表横幅已实际显示。

设置 → 通用 → **界面语言** 提供跟随系统、简体中文和 English，选择后立即更新界面、菜单及错误提示，无需重启；任务名称、用户输入、文件路径及终端配置不随语言选择改写。

## 启动与继续任务

悬浮入口右键 → **新建或继续任务…**，或从空槽窗口选择器进入启动界面，选择 Terminal / Codex / Claude Code、项目目录与程序的绝对路径。CLI 会话 UUID 留空时新建，填写或从 **发现本地会话…** 选择时续接确切会话；CLI 本身须已安装。已运行任务的右键 **配置启动与续接…** 只保存配置，供窗口确认关闭后或最近关闭中使用，不立即启动另一份任务。

启动分为两步：先新建空 Terminal 窗口并唯一确认新窗口与 TTY，将新任务 UUID、窗口身份和启动配置安全保存后，才向该新 TTY 发送一次性启动请求。启动使用结构化参数与明确项目目录，不自动提交提示词、不更改 CLI 的授权或信任策略。已有窗口仍可用、仅临时失去辅助功能响应、同一会话已被其他任务管理，或目标槽在等待期间被用户占用时拒绝重复启动。保存失败时不发送启动命令；已经打开的空窗口保留，供用户检查或重新连接。

启动记录位于 `task-launches.json`，最近任务可带回项目、可执行文件与确切续接 UUID。这里的“继续”是由 CLI 自身续接保存的会话，不是恢复已关闭进程的内存、终端滚动内容或未保存的交互状态。

## 自定义快捷键

设置 → 快捷键可选择预设，也可逐项修改任务 1–9、排列 / 恢复、按住呼出轮盘、入口显隐和任务总览。点击操作旁的 **修改**，在录制区按下组合，或使用修饰键与按键列表选择，再点 **保存快捷键**。编辑期间会暂停 OmniVibe 自身的全局快捷键；Esc 或取消退出录制，不保存本次草稿。

每项的省略号菜单提供 **停用此快捷键** 和 **恢复方案默认值**，页面还提供 **恢复全部方案默认值**。保存快捷键、停用和恢复操作都会立即保存并重新注册，不必再点外观设置的保存按钮。**切换到另一预设会清除全部自定义及停用项，恢复新预设的按键。** 恢复某一项若与其他自定义组合重复，也会拒绝并说明原因。

全局组合至少包含 Control、Option、Shift、Command 中的一个修饰键，不能只录制修饰键。Esc 保留用于取消；含 Command 的 Q、Tab、Space 组合也会拒绝。OmniVibe 内两个操作使用相同的物理按键和修饰键时，不覆盖原设置，而是显示重复原因。其他程序或系统占用属于实际注册冲突，会逐项显示警告，其余成功注册的按键仍可使用。快捷键设置和显示标签使用同一份配置；录制保存、注册成功与真实物理按键触发仍是不同的验证环节。

快捷键页同时显示录制是否暂停、最近一次响应和当前已收纳任务的编号、名称与应用。拖动排序后应按当前编号进入任务，不沿用旧编号；总览中的切换失败原因不会被悬停等临时提示覆盖，可按原任务身份重试。

## 调整槽位与移出管理

编号始终为 1–9，任务调整位置后使用新编号对应的快捷键。

| 操作 | 结果 |
| --- | --- |
| 在图录拖动已占用卡片的主预览区，放到任意槽位 | 插入该编号，中间槽位依次顺移；目标会高亮，不会因放下而激活窗口 |
| 在展开轮盘中把任务拖到其他槽位 | 同样按插入顺序排序 |
| 图录卡片右键 → 移动到空槽位 | 只移动该任务，原位置变空，其他任务不顺移；已有任务的目标不会被覆盖 |
| 将轮盘任务拖出整个轮盘区域并继续拖远后松手 | 移出 OmniVibe 管理，保留原窗口 |
| 点击槽位的 ×，或右键选择移出 / 解除绑定 | 移出管理，保留原窗口 |

例如将 2 号拖到 5 号，原 3、4、5 号任务依次前移，原 2 号成为新的 5 号。这是插入排序，不是交换两个任务。

移动和排序保留任务 UUID，配装选择、自定义图片、状态、未读提示及 Agent 会话跟随任务，而非留在旧编号；已生成的 hooks 命令继续指向该任务。拖动或菜单中的旧任务已被移除 / 替换时会拒绝操作，避免误操作后来占据该编号的任务。

移出管理不关闭应用窗口，也不结束 CLI 会话。若原布局尚未恢复或配置无法保存，任务绑定会保留并显示具体失败原因；任务操作和排列错误共用提示窗口。移除后重新绑定属于新任务，旧 hooks 不会自动关联它。

## 连接 Claude Code / Codex 状态

在已占用的轮盘槽位或图录卡片上右键 → **连接自动任务状态…**，选择 Claude Code 或 Codex，按需选择项目目录，然后复制连接命令，在对应终端中自行运行。打开此界面、复制命令或启动 OmniVibe 都不会自动运行 Agent，也不会接管一个已在运行的终端会话。CLI 需已安装且能从该终端的 `PATH` 找到。

生成的命令使用应用可执行文件的 `track` 子命令，包含 `--provider codex` 或 `--provider claude`、任务的 `--task UUID` 和数据目录 `--root`。项目目录通过可选的 `--cwd` 指定，留空沿用终端当前目录；收到会话 ID 后可选“继续已关联的会话”，传入 `--resume`。需要转交给 Agent 的额外参数放在命令末尾的 `--` 之后。将 `track` 换为 `plan` 只输出启动计划 JSON，供检查，不启动 CLI。

这些 hooks 只对本次启动的会话注入：Claude Code 使用 `--settings`，Codex 使用 `--no-daemon` 和 `-c hooks.…`，不改写全局 CLI 配置。Codex 连接前通过自身 app-server 的只读 `config/read` 接口读取项目有效配置，保留已有事件 hooks，再追加 OmniVibe 观察器；无法确认原配置时停止启动，不用空数组覆盖。Codex 首次运行后仍需由本人在 `/hooks` 中查看并信任本地状态观察器；OmniVibe 不自动信任 hooks、不批准工具操作，也不改变 CLI 的授权策略。本机参数核对版本为 Codex 0.162.1、Claude Code 2.1.296，旧版本可能不支持相同接口。此预览暂不支持转发 Codex 的 profile、worktree、remote 或 `--cd`，目录请用 OmniVibe 的 `--cwd`；普通配置覆盖会同时用于读取，但自行覆盖 `hooks` 可能取代状态观察器。

状态事件绑定不可复用的任务 UUID，不依靠窗口标题或槽位编号认领 Agent。重新绑定或移除后，旧命令的事件不会跟随到新任务，需重新复制连接命令。Hooks 的状态记录仅保留任务 UUID、提供方、会话 / 轮次 ID、事件名、时间及固定状态提示，不保存提示词、回复或 transcript 正文，也不读取终端正文推断进度。

已有 CLI 不必重开：任务右键的本地会话选择界面会自动发现 Codex / Claude 的元数据，首次由用户明确选择对应会话；已经保存确切 provider + 会话 UUID 的任务可自动关联同一记录，不按名称或窗口标题相似度认领。只提取会话 ID、项目、名称、时间和白名单状态字段，不显示或保存提示词、回复、工具输出正文。关联后从记录末尾跟踪新状态，初始显示未知；来源明确标为 **会话记录**。同一会话收到真实 hooks / notify 后优先使用这些事件，迟到的记录更新不会覆盖它或重复提醒；用户显式重新关联记录时可切回记录来源。

未收到事件时状态为未知。收到事件后显示运行、等待确认、本轮已回复或错误；“本轮已回复”只表示该轮 CLI 回复结束，仍需查看结果，不能证明整个任务完成。应用约每 0.5 秒读取一次本地事件，实际更新还受 CLI 发出事件、磁盘与应用调度影响。Hooks 不是心跳，自动运行 / 等待状态持续 10 分钟没有新事件会显示“状态待确认 / 可能过期”，不会据此判定失败或完成。会话中断 / 结束时恢复未知状态。

没有 hooks 或需要手动标记时，可在仓库根目录执行：

```sh
./artifacts/macos/OmniVibe.app/Contents/MacOS/OmniVibeMac \
  status --slot 1 --state waiting --message "需要确认"
```

`--state` 支持 `running`、`waiting`、`ready`、`error`、`unknown`。此命令在执行时将已占用槽位解析为当前任务 UUID，写入带“手动标记”来源的状态；自定义数据目录可加 `--root`。它不会启动 Agent，也不会验证 Agent 的实际进度。

## Apple Terminal 配色

**默认保留系统 Terminal 原生无皮肤外观。** 终端主题联动默认关闭，轮盘换肤不修改 Terminal。插画背景与部分终端 TUI 的浅色输入区会发生视觉冲突，推荐保留原生外观；已启用时可点“恢复原完整配置”，恢复两个原标签页配置并持久化关闭联动。

设置 → 主题与换装提供 **Terminal 完整主题 · 一次导入后联动**。13 个主题分别生成装饰和简洁版，共 26 个 `.terminal` profile，包含原主题的 16 色 ANSI、前景 / 背景、光标、选区颜色，以及 Menlo 13 pt 等宽字体和静态 PNG 背景。简洁版使用对应边框素材；这些图案属于终端内容背景，不会改变 macOS 系统标题栏或窗口外框。窗口不透明度为 100%，预合成图片不再次叠加源数据的 0.12 图片透明度。

首次使用顺序：

1. 点击 **导出 26 套配置**，生成 `~/Library/Application Support/OmniVibe/TerminalProfiles/` 并在 Finder 打开。此步骤不导入 profile、不新建 shell；如存在快速四色配色备份，会先尝试恢复原色，失败则停止。保留目录中的 `Assets`，profile 的图片书签指向这些稳定文件。
2. 用户自行在 Terminal 官方 **设置 → 描述文件** 中导入 26 个 `.terminal` 文件，再点 OmniVibe 的 **检查导入**。若原标签页使用无法独立定位的配置副本，优先点 **自动备份原配置**：通过 Terminal 自身复制该标签页的原配置，核对确切会话、窗口、TTY、独立副本身份、公开配色与字体，再保留完整配置字节和校验摘要，登记为 NativeCopy 恢复依据。此步骤不切换主题、不创建 shell，也不因原有同名 Basic 等配置而猜测完整配置相同；核验失败保留原标签页与已有备份供重试。
3. 自动备份不可用时，可用 **指定原配置备份…**：通过 Terminal 的 **Shell → 导出设置** 保留完整原文件，在描述文件中导入为独立且名称唯一的备份配置，再逐标签页选择原文件和备份配置，勾选确认后保存恢复基准。此后按用户明确指定的配置恢复，不宣称能自动证明副本中未公开字段完全相同。
4. 先保存并应用 OmniVibe 的外观草稿，再点 **应用并开启联动**。仅对已打开的 Terminal 标签页切换到当前主题与装饰对应的 profile，事先备份原 profile 与窗口位置。应用成功后才开启并保存联动；以后主题 / 装饰变更先应用 Terminal，失败时保留原 OmniVibe 主题。
5. **恢复原完整配置** 按已确认的原配置、NativeCopy 或用户指定恢复基准恢复，并关闭联动；失败时保留备份供重试。主题应用允许原目标范围内的字符网格尺寸对齐，恢复使用更严格的原位置与尺寸校验。Terminal 已重启导致旧会话备份不可用时，可明确归档旧备份；归档保留文件，不冒充恢复成功。

未开启完整主题联动时，普通 **立即应用此主题** 只修改 OmniVibe。打开应用不会自动导入或应用 Terminal profile。高级选项仍提供独立的 **应用快速配色 / 恢复快速配色**，仅修改已打开 Terminal 所用 profile 的背景、普通文字、粗体文字和光标；共享 profile 的窗口可能一起变色，不能与未恢复的完整配置备份混用。

检查导入、自动备份、应用或恢复可能触发 macOS 自动化权限提示，需要用户本人确认允许 OmniVibe 控制 Terminal，与辅助功能、输入监控、屏幕录制和通知权限分开。本机已真实识别用户导入的全部 26 套配置，并在两个真实标签页完成自动原配置备份、完整黑神话主题应用和原配置恢复的读后核验；最后一次完整应用 → 恢复已确认两个标签页恢复原配置，恢复依据均为原生自动备份，主题联动已关闭。背景图像的实际目视呈现尚未验收；配置读后核验与隔离测试不能代替图像目视检查。

终端主题当前仅适配 Apple Terminal；主题操作不读取终端正文或执行命令，与用户明确发起的任务启动分开。导出使用静态 PNG；保留的 GIF 素材不表示已支持动画，动态背景、Windows 着色器及系统窗口外框不在 Apple Terminal 适配范围内。iTerm 等其他终端暂无主题联动。

### Claude Code 自定义主题

设置 → 主题与换装 → **Claude Code 主题** 可明确选择生成并联动当前套装配色。只写 `CLAUDE_CONFIG_DIR` 或 `~/.claude` 下的 `themes/omnivibe.json`，不改 Claude 的主题选择或其他设置；首次在 Claude Code 的 `/theme` 选择 **OmniVibe**。如果首次创建 `themes` 目录，需要重启 Claude Code 一次；之后通过同一文件更新配色。

首次写入前保留原文件，连续换肤仍保留最初备份；**恢复 Claude 原主题文件** 可还原原字节，或移除本工具新建且未被修改的主题文件。检测到用户或其他程序修改目标文件时停止覆盖并保留备份。主题生成不启动模型，不产生会话或提示词。

## 声音

13 套主题均接入仓库中的 CC0 操作声与独立完成提示。窗口切换沿用原版标志音策略：优先使用该主题的用户自定义 WAV；只有 `ink-jade`、`midnight`、`cinnabar` 三套经典主题内置 CC0 标志音，其余主题未导入时切换保持静音，不借用别的主题或替换为旧版程序生成的 `switch.wav`。包内不包含官方游戏音频。

声音默认开启，共享音量为 45%，完成提示使用该音量的一半。设置 → 声音中可独立于界面动效关闭声音、调整音量、查看当前切换音是否可用，并点击按钮试听；打开设置或切换设置草稿不会自动试听。关闭声音或音量为零时，正常操作不读取音频；音频读取与播放在后台执行，失败不阻塞窗口操作，也不请求麦克风权限。

可为当前主题导入本地 PCM 16 位 WAV（单 / 双声道、16–96 kHz、最长 3 秒、文件不超过 1.2 MB）。只有点击保存才复制至 `~/Library/Application Support/OmniVibe/Audio/<主题 slug>/signature.wav`，已有自定义文件会先备份；取消不写入导入文件或设置草稿。

## 窗口预览

窗口预览需要 macOS 14 或以上。图录中的 **开启窗口预览** 是显式开关，只有用户点击并取得系统屏幕录制权限后才启用；已有系统权限也不会在新启动时自动开启。macOS 13、未授权或关闭预览时仍可使用任务收纳与切换。

预览仅为已绑定且能唯一确认身份的窗口获取缩略图，不采集整块显示器或音频，不写入图像文件。图录可见且 OmniVibe 位于前台时约每 2 秒刷新；关闭图录、应用进入后台或关闭预览会停止刷新并释放图像。无法确认窗口、窗口已变化或捕获失败时显示占位提示，不能通过相似标题替代目标窗口。

## 验证

```sh
./scripts/macos/validate.sh
# 需要可交互桌面、关闭其他 OmniVibe 实例，并已为该应用授权辅助功能：
./scripts/macos/validate.sh --desktop
```

默认执行核心与协调器单元测试、原生 `.app` 构建和打包素材检查（13 套主题、117 个器物、身份图、边框及背景的实际解码），素材报告位于 `artifacts/macos/appearance-results.json`。桌面检查使用两个独立辅助应用创建一次性 AppKit 窗口，验证主测试应用中两个窗口的具体身份、同应用切换、跨进程切换、排列、最小化与恢复，完成后关闭测试窗口。它不排列用户已有的终端或应用窗口。证据保存到 `artifacts/macos/desktop-smoke-results.json`。缺少权限时结果为 `requires-permission`，进程返回 2，不能当作通过。
